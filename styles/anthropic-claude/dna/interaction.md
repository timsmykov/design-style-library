# Interaction

## Action model

- One dominant action per decision zone.
- Primary action is black/charcoal on light surfaces or ivory/white on dark surfaces.
- Clay/orange action can be used for execution/send/run in product workbench surfaces.
- Secondary actions are text, outline, or low-contrast buttons.
- Destructive or irreversible actions require confirmation and should not sit beside primary generation actions.

## Workbench model

- Composer is a compact command center, not just a text box.
- Embed context inside the composer: model, project, branch, environment, attachment/file/source controls.
- Generated work should open into artifact/document/code surfaces with status and context.

## Onboarding model

- Minimize fields.
- Offer familiar auth first when relevant.
- Keep privacy/legal text visible but visually quiet.
- Avoid urgency, countdowns, or pressure mechanics.
